# AssetFlow 평가 프로토콜

> 다음 평가 확장 목표와 블라인드 작성 절차는 [EVALUATION-EXPANSION.md](EVALUATION-EXPANSION.md)를 따른다. 기존 16건의 측정 결과는 새 48건 평가를 실행하기 전까지 그대로 유지하며, 목표 수치를 실제 결과처럼 표기하지 않는다.

## 평가 목적과 범위

본 문서는 서비스 품질 검증 계획이다. 학술 연구, 논문 작성·투고 또는 HCI 연구를 목표로 하지 않는다. 최소판은 기능·근거·권한·정합성·복구·비용·지연·재시도를 평가한다. 사람의 승인·수정 흐름은 제품 사용성 요구사항이며 그 존재 자체가 HCI 연구 실적은 아니다.

승인·수정·이관 흐름의 설계 의도와 사람 수정량 측정치는 설계 근거로 설명할 수 있다. 이를 HCI 연구 실적이나 사용자 연구 결과로 표현하지 않는다.

## 최소판 평가 구성

- B0: 단일 에이전트가 지급 이력 도구·규정 검색·승인·검증 기능을 사용한다. 최소판은 B0 자체 품질을 보고한다.
- 승인과 정합성 보호는 항상 적용한다. 안전장치를 제거한 구성과 비교해 개선을 과장하지 않는다.

## 제품 구성 비교 — 확장판

상태 기반 업무 흐름과 역할 분리가 단일 에이전트 대비 처리 품질을 개선하는가? 그 개선에 필요한 지연·비용·사람 수정량은 얼마인가?

- B1: LangGraph의 요청 처리와 규정 조사 역할을 분리한다. B1 비교는 최소판 완료 조건이 아니다.
- 두 구성에 같은 모델, 정책/데이터 스냅샷, 도구 권한, 호출 예산, 입력을 적용한다. 차이가 있으면 명시한다.
- 승인과 정합성 보호는 두 구성에 공통 적용한다.

## 평가셋

최소판은 개발 16건·최종 16건을 목표로 하고, 개발 약 60건·최종 약 40건은 확장 규모로 둔다. 정상·정보 부족·재고 부족·부분 처리·규정 불명·중복 요청·도구 실패를 포함한다. 유형별 실제 건수와 분모를 보고한다. 시스템 검증 목록과 범위는 TRACEABILITY.md를 기준으로 관리하며 건수보다 위험 유형의 완전한 포함을 우선한다.

## 측정 항목

| 항목 | 측정 정의 |
|---|---|
| 처리 경로 정확도 | 사전 정의한 허용 경로와 일치한 건수/평가 건수 |
| 추가 질문 적절성 | 필수 정보 요청 누락·불필요한 질문을 각각 기록 |
| 근거 정확도 | 인용한 규정 ID/버전의 실제 존재와 주장 지지 여부를 별도로 판정 |
| 계산 정확도 | 수량·자산가·미처리 잔량의 정답 일치 |
| 업무 완료 | 기대한 최종 상태에 도달한 사례 비율; 이관 정답도 성공으로 구분 |
| 사람 수정량 | 승인 전 수정 유무·항목 수·측정 시간 |
| 지연 | 활성 처리 구간의 종단 시간 및 도구/모델 구간; 사람 대기 시간 별도 |
| 비용 | 건당 모델/임베딩 호출 비용, 재시도 포함 |
| 재시도·실패 | 노드별 재시도 횟수와 실패 원인 분포. `node_trace` 기록 기준 |

실패와 타임아웃도 분모 및 비용에 포함한다. 소규모 표본의 p95는 표본 수·반복 수와 함께 보고한다. 유의한 개선을 미리 약속하지 않는다.

## 반드시 통과할 시스템 검증

[검증 대응표](TRACEABILITY.md)가 필수 목록의 단일 기준이다. SYS별 CF 연결, 입력 조건, 기대 DB 변화, 최소/확장 게이트를 명시한다. 최소판은 비용 청구 실행을 차단하며 청구 원장 잔액 검증은 실행 확장 전에 통과한다. 계획 매핑 완료와 실제 테스트 통과를 구분한다.

## 실행 및 분석

모델·프롬프트·도구·규정·데이터·임베딩 모델·스키마 버전과 실행 설정을 저장한다. 최소판은 1회 기준으로 한계를 기록하고 확장판에서는 가능하면 각 사례를 3회 반복하되 첫 실험 전에 비용 상한으로 확정한다. 반복 실행은 독립 사례 수로 부풀리지 않는다. 쌍체 비교는 사례 단위로 집계하고 신뢰구간을 산출할 경우 사례를 재표집한다.

품질 하락·비용 증가도 보고한다. 역할 분리에 이득이 없으면 단일 에이전트를 최종 구성으로 채택할 수 있다.

## AX 효과 검증 — 확장 항목

필요한 경우 제품 개선 목적으로 소규모 동일 난이도 과업에서 수동 처리와 보조 도구 사용 시간을 비교한다. 학술 사용자 연구나 논문 산출물로 취급하지 않는다. 착수 전에 자기 측정/외부 참여자 여부, 모집 방식과 측정 절차를 정하고, 자기 측정이면 그 한계를 표시한다. 순서 효과를 줄이도록 수행 순서를 교차하고 참여자 수·사례 수를 공개한다. 월간 절감 추정은 측정된 시간 차이 × 가정한 처리량이며, 실제 운영 ROI와 구분한다. 합성 데이터 결과를 실고객 처리 성능으로 표현하지 않는다.

## 최종 산출물

평가 설정, 사례별 결과, 집계표, 대표 오류, 비용/지연/재시도, 시스템 테스트 결과, 한계가 있는 재현 가능한 리포트. 수치 목표는 베이스라인 이후 정하며 현재 성능 수치는 없다.

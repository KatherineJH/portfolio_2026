# AssetFlow 사내 IT 자산 요청 — 시나리오와 판단표

## 확정 방향

2026-09-11 사용자 합의: 도메인은 사내 IT 자산 요청 처리다. 요청자는 임직원, 승인자는 IT 담당자다. 가상의 회사이며 실제 사내 규정이나 자산 원장을 사용하지 않는다.

자산 범주: LAPTOP(노트북), PERIPHERAL(독·모니터·키보드 등 주변기기), MOBILE(업무용 단말). MVP는 개별 자산 단위로 한정한다. 구매 요청, 라이선스 배분, 반납 정산, 특수 사양 주문 제작은 담당자 이관 대상으로 둔다. 자산의 고장 유형이나 데이터 초기화 필요 여부는 확인 정보로 보존하되, 자산 범주만으로 요청을 거절하지 않는다.

## 공통 가상 규칙

- 요청 자산이 해당 임직원에게 지급된 것인지 확인한 뒤 조회·처리한다.
- 요청자 진술과 IT 담당자 점검 사실을 분리한다. 사진 판독은 구현하지 않는다.
- 지급 이력별 미처리 수량을 기준으로 계산한다. 이미 교체 처리된 수량은 다시 처리하지 않는다.
- 교체 재고가 없으면 요청자 동의 없이 다른 모델로 대체하지 않는다.
- IT 담당자 승인은 처리안 버전에 연결한다. 수정 후 재승인이 필요하다.
- 모의 지급 등록만 수행하며, 등록 완료와 실물 전달 완료를 구분한다.
- 사용 기간 기준 교체 주기, 파손 귀책과 비용 청구, 데이터 이관 책임은 아직 상세 규정이 없다. 미정 조건은 담당자 검토로 남긴다.

## 대표 시나리오

| ID | 요청·사실 | 다음 동작 | 금지 행동 |
|---|---|---|---|
| AR-01 | 지급된 독 2개 중 1개 충전 불량 교체 요청. 본인 지급 자산·지급 완료·담당자 점검 완료·미처리 2개·교체 재고 5개 | 1개 교체 처리안 → 담당자 승인 → 현재 재고 재검증 → 모의 지급 등록 | 승인 전 실행, 2개 전체 교체 |
| AR-02 | 모니터 교체를 원하나 어떤 지급 자산인지 식별할 수 없음 | 최소 식별 정보 질문 → 지급 관계 확인 | 추측한 자산 조회·처리 |
| AR-03 | 노트북이 고장났다는 요청자 진술만 있고 점검 상태 미확인 | 점검·담당자 확인 요청 | 요청자 진술을 점검 완료 사실로 변환 |
| AR-04 | 교체 조건은 확인됐으나 해당 모델 재고 0개 | 재고 없음 안내와 대체 모델 제시 → 요청자 선택 확인 → 해당 처리안 재검토 | 임의 모델 대체 |
| AR-05 | 지급 키보드 3개 중 1개 파손, 비용 귀책 문의. 개당 자산 취득가 80,000원, 기처리 없음 | 수량·사유·규정 확인 후 자산가 80,000원 초안. 파손 귀책·비용 청구 조건 미정이면 이관 | 청구 금액을 임의 확정 |
| AR-06 | AR-01과 동일 실행 요청이 다시 도착하고 기존 지급 등록 존재 | 접근 권한 확인 후 기존 등록 반환 | 신규 지급 등록·재고 이중 차감 |
| AR-07 | 키보드 지급 3개 중 2개가 기처리됐는데 2개 추가 요청 | 미처리 1개와 불일치 설명 → 수량 질문/이관 | 요청 2개 그대로 처리 |
| AR-08 | 독 1개 교체 승인 후 2개로 변경 | 이전 승인 무효화 → 수량·재고 재검증 → 새 승인 | 이전 승인 재사용 |

AR-01 금액 참고: 개당 자산 취득가 120,000원. 교체 사례이므로 이를 비용 청구로 해석하지 않는다. 모든 수량·금액은 가상 값이다.

## 판단표와 적용 순서

| 우선순위 | 규칙 | 조건 | 결과 |
|---|---|---|---|
| 1 | R-01 | 자산 식별 또는 지급·접근 권한 미확인 | 추가 확인, 업무 변경 차단 |
| 2 | R-02 | 동일 실행 키에 기존 등록/진행 기록 존재 | 기존 상태 조회·결과 대조, 신규 실행 차단 |
| 3 | R-03 | 수량 불일치 또는 필수 사실 부족 | 추가 질문/점검 대기 |
| 4 | R-04 | 규정 미정·충돌 또는 미지원 계산 | 담당자 이관 |
| 5 | R-05 | 교체 재고 부족 | 대체 안내와 요청자 선택 확인 |
| 6 | R-06 | 필요한 사실·규정·재고가 모두 충족 | 처리안 작성, 승인 대기 |
| 7 | R-07 | 승인 이후 처리안 또는 관련 상태 변경 | 기존 승인 유효성 재검토, 수정 시 재승인 |
| 8 | R-08 | 유효 승인과 실행 직전 검증 통과 | 동일 키로 모의 지급 등록, 결과·트레이스 기록 |

결과 불명 타임아웃은 R-02에서 조회·대조한다. 처리 결과를 확인하지 못하면 실패/성공을 단정하지 않고 확인 대기로 유지한다.

## 규정과 아키텍처의 분리

운영 규정 미정: 사용 기간 기준 교체 주기, 파손 귀책 판정, 비용 청구 시점, 데이터 이관 책임. 미정이면 이관한다. 최소판의 비용 청구는 초안·이관만 지원한다.

재고 배분 시점, 실행 키, 승인 버전, 상태·트랜잭션 경계는 [ADR-001](adr/001-claim-execution.md)에 있다. 상태는 Accepted(2026-09-09)이며 결정은 승인 대기 중 예약 없음, 실행 시 원자적 배분, 동일 실행 키 재시도다.

업무 AR-01~08과 별개로 장애·보안·경합의 입력과 기대 결과를 [검증 대응표](TRACEABILITY.md)에 정의했다. AR은 사용자 흐름, SYS는 필수 시스템 검증으로 함께 사용한다.

## 규정 코퍼스

정책 조항은 10~15개로 작성하고 pgvector로 검색한다. 각 조항은 ID, 버전, 적용일, 조건, 예외, 필요한 정보, 허용 행동을 갖는다. 처리안은 인용한 조항의 ID와 버전을 반드시 포함한다. 근거를 찾지 못하면 이관한다.

이 문서는 개발용 초안이며 최종 평가셋과 분리한다.

01 · QUALITY PROBLEM

Agent의 품질은 답변이 아니라,
업무 상태가 바뀌는 순간 드러납니다.

자산 요청에서 한 번의 오판은 잘못된 승인, 중복 지급, 음수 재고로 이어집니다. 그래서 실패 가능성을 먼저 정의했습니다.

01

근거 없는 판단

모델이 관련 없는 규정을 인용하거나 대상 자산을 추측할 수 있습니다.

02

권한 우회

브라우저가 전달한 역할이나 사용자 ID를 신뢰하면 승인 경계가 무너집니다.

03

중복 실행

타임아웃 재시도와 동시 요청이 같은 지급을 두 번 실행할 수 있습니다.

04

수량 경합

동시에 승인된 요청이 같은 재고와 지급 가능 수량을 약속하면 실행 단계에서 충돌할 수 있습니다.

03 · QUALITY GATES

실행까지 통과해야 하는
네 개의 품질 게이트

  1. 01

    Evidence Gate

    지급 관계·점검 상태·재고와 검색된 정책을 분리해 조회합니다. 근거가 부족하면 처리안을 만들지 않습니다.

    RAG · target verification
  2. 02

    Decision Gate

    모델 출력은 작은 사실 집합으로 제한하고, 결정적 규칙이 need_info·need_review·escalate·propose 경로를 선택합니다.

    bounded output · server rules
  3. 03

    Approval Gate

    승인 권한을 DB에서 확인하고 처리안 버전·digest에 결속된 재고와 지급 수량을 함께 예약합니다.

    authorization · reservation
  4. 04

    Execution Gate

    승인에 연결된 예약과 자산 소유, 규정 버전, 실제 보유량을 잠근 뒤 다시 검사하고 원자적으로 소비합니다.

    idempotency · row lock
